# 架构与边界

ArkMC Studio 是 Windows x64 本机桌面管理程序，没有面向公网的管理 HTTP 服务。版本事实源是根目录 `package.json`；桌面、预加载桥、管理服务和便携程序使用同一版本。

## 进程与模块

| 入口                                | 职责与生命周期                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------------- |
| `src/main/index.ts`                 | Electron 主进程，窗口、托盘、可信 IPC、目录选择、版本切换和退出协调                |
| `src/preload/index.ts`              | 通过 `contextBridge` 暴露受限 `window.ark` 桥，不向渲染器暴露通用 Node.js 接口     |
| `src/renderer/`                     | React 工作台、十五页导航、草稿与只读分析；不直接访问游戏目录或凭据                 |
| `src/agent/index.ts`                | 本机管理服务，实例、SQLite、任务、备份、内容、工具与网络配置                       |
| `src/server/host.ts`                | 持有游戏标准输入输出的独立会话宿主；管理服务重新连接时核验身份、父子关系和实例路径 |
| `src/network/worker.ts`             | 一次性的线路、工具和网络控制操作，不接管游戏控制台                                 |
| `src/direct/host.ts`                | 原生 IPv6 HTTPS/UDP 入口，独立于桌面进程                                           |
| `resources/signal-router/router.py` | Python 信令适配；只重写匹配的 UDP 候选，保留服务器身份、DTLS 和 ICE 凭据           |
| `tools/nethernet-route-check/`      | Go 网络诊断探针；验证传输握手，不代表真实 Minecraft 账号已登录                     |

渲染器经预加载桥调用主进程，主进程检查发送窗口和主框架，再通过本机鉴权命名管道调用服务。参数校验主要位于 `src/agent/api.ts`；数据结构位于 `src/shared/types.ts`。这些 RPC 是应用内部协议，不承诺供第三方稳定调用；本项目没有公开 REST API 或 SDK。

## 数据与操作安全

用户选择的服务器目录独立于源码和工作台安装目录。管理数据库、备份和会话状态位于用户数据目录；工具、下载、运行环境和已部署后台资源位于工具目录。路径与覆盖优先级见 [配置参考](configuration.md)。

- 配置与文本编辑保存前检查并发修改；界面保留未保存草稿离开确认。
- 恢复和核心替换使用完整快照或恢复前保护；不能以代码回滚代替世界和数据库恢复。
- 备份先复制并校验文件，再打包并记录清单、大小与 SHA-256；取消或失败按任务状态报告。
- 后台快照与桌面任务事件使用相同的显示窗口：按创建时间倒序展示最近 150 条记录，并保留窗口之外仍在运行或排队的任务。列表截取不删除数据库记录。
- 用户凭据使用 Windows 当前用户 DPAPI 保护，不应复制到另一 Windows 用户后直接复用。
- 从 1.4.0 起，独立游戏会话可在管理服务替换后重连；更旧的活动会话不能无损转移已打开的管道，必须按界面指引完成首次切换。
- 正常退出程序通过生命周期协调器保存关服并停止托管线路；关闭窗口默认缩到托盘。

## 构建与源码边界

四个独立后台入口通过 esbuild 生成 `dist-agent/`、`dist-server/`、`dist-direct/` 和 `dist-network/`；electron-vite 生成 `out/`。这些目录由构建生成，不手工编辑或提交。

`prepare:resources` 从当前锁定依赖收集 npm 许可，复制当前 Node.js 和 uv，按实际运行时版本下载许可，重新编译 Go 探针并汇总 Go 依赖声明。生成的二进制、图标和 `resources/notices/` 不进入 Git，由发布流程重建。MIT、Electron/Chromium 和其他第三方声明随便携程序保留。

`.gitignore` 列出本机一次性维护脚本。这些脚本保留在原位置供本地维护，不作为项目公开接口、CI 或发布输入。运行数据、世界、隧道配置和备份也不纳入公开仓库。

## 设计取舍与验证

沿用本机多进程架构，避免管理服务更新导致游戏控制台丢失；它要求重连前验证宿主身份与能力，并明确旧架构迁移边界。SQLite、DPAPI、PowerShell 采样和便携资源部署使当前支持范围限定为 Windows x64。

单元测试检验业务和文件行为；`test:session` 使用真实隔离标准输入输出样本验证管理进程替换；`test:program-ui` 验证版本门槛与退出；`test:ui` 覆盖布局与交互；`test:portable` 验证打包产物。具体命令见 [贡献指南](../CONTRIBUTING.md)，发版见 [发布指南](releasing.md)。
